# AI 티 패턴과 처방

남의 글을 다듬을 때 찾아서 고칠 패턴이다. [im-not-ai](https://github.com/epoko77-ai/im-not-ai)의 `quick-rules.md`에서 기술 문서와 업무 글에 해당하는 항목을 골라 옮겼다. 괄호 안의 ID는 원본 분류 체계의 ID다. 칼럼, 에세이, 문학에만 해당하는 패턴은 뺐다.

**손대지 않는 것:** 고유명사, 제품명, 모델명, 기관명, 수치, 날짜, 단위, 발화자가 있는 직접 인용, 법률 조문, 수식, 업계 표준 약어(LLM, GPU, API 등), 코드와 명령어.

**서법을 보존한다:** 당위("~해야 한다")를 사실("~한다")로, 추측("~일 수 있다")을 단정으로 바꾸지 않는다. 같은 표지가 반복되면 서법은 그대로 두고 표현만 바꾼다.

## 번역투

| 패턴 | 처방 | 예 |
|---|---|---|
| "~에 있어(서)" (A-3) | "~에서", "~을 볼 때" | 운영 방식에 있어서 → 운영 방식에서 |
| "가지고 있다", have/make+명사 직역 (A-7) | 형용사나 동사로 되돌린다 | 중요한 의미를 가지고 있다 → 의미가 크다 |
| 이중 피동 "~되어지다", "~지게 되다" (A-8) | 단일 피동이나 능동 | 발생되어졌으며 → 발생했으며 |
| "~에 의해" 피동 (A-9) | 행위자를 주어로 | AI에 의해 생성된 → AI가 만든 |
| "~와 관련하여", "~와 관련된" (A-5) | "~에", "~의", 또는 동사로 풀어 쓴다 | 배포 일정과 관련하여 알려 드립니다 → 배포 일정을 알려 드립니다 |
| "~에 대해(서)"가 한 문단에 3회 이상 (A-1) | 목적격 조사로 | X에 대해 논의했다 → X를 논의했다 |
| "~을 위해" 목적절 남발 (A-11) | "~려고", "~도록" | |
| 추상 주어 + "보여준다, 제공한다, 가져온다" (A-15) | 구체적인 주어로 | 측정 결과는 지연 시간 개선을 보여준다 → 측정해 보니 지연 시간이 줄었다 |
| 명사 앞에 3어절 이상 관형절 (A-18) | 문장을 나눈다 | |
| "~에서의", "~으로의" 이중 조사 (A-19) | 절로 풀어 쓴다 | 운영에서의 문제 → 운영하다 생긴 문제 |
| "단순한 X를 넘어 Y" (A-21) | "X만이 아니라 Y다"로 풀거나 뺀다 | |

## 영어 용어

| 패턴 | 처방 |
|---|---|
| 한글 뒤 괄호 영어 병기를 매번 반복 (B-1) | 처음 한 번만 병기한다 |
| 광고성 영어(seamless, robust, leverage)나 음차한 동사(커버하다, 클리어하다) (B-2) | 한국어로 풀어 쓴다. 표준 기술 용어는 원어를 유지하고 기계적으로 직역하지 않는다(prompt를 "지시문"으로 바꾸지 않는다) |

## 구조

| 패턴 | 처방 |
|---|---|
| "A가 아니라 B", "~것이 아니라" 대구가 2회 이상 (C-8) | 한 번만 남기고 나머지는 평서문으로. 모두 없애지는 않는다 |
| 연결어미(-고, -며, -지만, -아서) 바로 뒤 쉼표 (C-11) | 쉼표를 뺀다. 다듬으면서 새로 만들지 않는다 |
| 문단 머리의 "먼저, 반면, 결국" 3단 공식 (C-7) | 접속사를 한두 개로 줄인다 |

## 상투구

| 패턴 | 처방 |
|---|---|
| "결론적으로, 따라서, 이를 통해, 요약하면" 결산어가 3회 이상 (D-1) | 한두 개만 남기고 뺀다 |
| "시사하는 바가 크다, 주목할 만하다, 괄목할 만하다, 매우 고무적이다, 매우 중요하다" (D-2) | 빼거나, 무엇이 왜 중요한지 구체적으로 쓴다 |
| "크게 세 가지로 나눌 수 있다, 다음과 같다" 도입구 (D-3) | 도입구를 빼고 바로 본론을 쓴다 |
| "필요한 것은 ~이다", "핵심은 ~다" 분열문 (D-8) | 주어와 서술어를 직접 잇는다: 필요한 것은 방향이다 → 방향이 필요하다 |
| "~로 이어진다", "~에 직결된다" 결산 (D-9) | 인과 경로를 구체적으로 쓴다 |
| 결말의 "향후, 앞으로" (D-11) | 빼거나 원문에 있는 실제 시점으로 바꾼다. 없는 시점을 지어내지 않는다 |
| "과제도 남아 있다, 한계도 분명하다" 같은 문패 문장 (D-12) | 문패를 빼고 실제 과제를 첫 문장으로 쓴다 |

## 완곡과 형식명사

| 패턴 | 처방 |
|---|---|
| "~로 보인다, ~로 판단된다" 같은 추측 종결의 반복 (G-1) | 단정으로 바꾸지 않고 종결 형태만 바꾼다 |
| "~할 가능성이 있을 수 있다" 이중 완곡 (G-2) | 완곡 표현을 하나만 남긴다. 남긴 표현의 확신 강도는 원문대로 둔다 |
| "주목할 점은 ~라는 점이다" (I-2) | "X는 ~다"로 직접 쓴다 |
| "~다는 것이다, ~다는 뜻이다" 결말 (I-3) | "~다"로 끝낸다 |
| 출처 없는 "~라는 분석이다, 평가다" (I-7) | 출처가 있으면 두고, 없으면 직접 서술한다. 출처를 지어내지 않는다 |

## 시각 장식

| 패턴 | 처방 |
|---|---|
| 문장마다 볼드 강조 (J-1) | 경고와 핵심 결론만 남긴다 |
| 따옴표 강조가 5회 이상 (J-2) | 진짜 인용만 남긴다 |
| 대시(—) 부가 설명의 반복 (J-3) | 쉼표, 괄호, 별도 문장으로 나눈다 |
| 이모지(헤딩, 목록 머리) (C-5) | 업무 문서에서는 뺀다 |

## 다듬은 뒤 점검

1. 고유명사, 수치, 날짜, 인용이 원문과 같은가. 문장마다 핵심 명사가 적어도 한 번 남았는가.
2. 주장의 강도, 추측과 단정, 당위가 원문과 같은가.
3. 원문의 격식(합쇼체, 해요체, 해라체)이 유지되는가.
4. 원문에 없던 비유, 상투구, 해석을 새로 넣지 않았는가.
5. 원문 대비 절반 이상을 바꿨다면 과하게 고친 것이다. 고친 근거가 있는 부분만 남기고 되돌린다.
