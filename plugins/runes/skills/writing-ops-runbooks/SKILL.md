# Writing Ops Runbooks

## Overview

런북은 읽히려고 있는 게 아니라 **쓰이려고** 있다. 독자는 문제를 안고 페이지를 열고, 답을 찾으면 닫는다.

**핵심 원칙: 문서를 주제가 아니라 독자의 행동 순서로 배치한다.**

정확한 내용이 문제인 경우는 드물다. 망가지는 건 거의 항상 **구성과 분량**이다.

## When to Use

**대상은 하나다 — 사람이 작업 도중에 열어서 보는 문서.** 배포 방법, 접속 방법, 장애 대응, 재설치 절차.

**When NOT to use:** 회의록·설계 문서·제안서(시간순이 아니라 논리순으로 읽힌다), 코드 주석·커밋·PR 본문(배경을 담는 자리다).

## 절 배치 — 독자의 시간순

```
1. 한 줄 요약      독자가 이 문서를 연 이유에 바로 답한다
2. 무엇을 하나      실제 행동. 명령은 복사해서 쓸 수 있게
3. 안 되면 어디를 보나   구간별로 순서대로 짚는 체크
4. 하면 안 되는 것   실패 모드. "이러면 뭐가 깨진다"
5. 왜 이런가        구조·배경. 여기서부터는 안 읽어도 된다
6. 운영자가 챙길 것   만료·갱신·미정 사항
```

**2번이 문서 뒤쪽에 있으면 실패다.** 재설치 체크리스트가 6절에 있고 앞 절반이 구성 설명이면 뒤집어야 한다.

## Quick Reference

| 규칙 | 이유 |
|---|---|
| 절 번호(`3.1`, `5.2`)를 달지 않는다 | Confluence 목차 매크로가 한다. 수동 번호는 절을 옮길 때마다 깨진다 |
| 표는 **판단 기준이 있을 때만** | `앱 \| 이유`는 표. `항목 \| 값` 나열은 그냥 문장이나 목록 |
| 앞 내용을 요약하는 표를 만들지 않는다 | 같은 사실이 두 곳에 있으면 한쪽이 반드시 낡는다 |
| 흐름은 ASCII 다이어그램 | 단계마다 **소요 시간**을 적는다 — 독자가 "안 되나?" 하고 손대는 걸 막는다 |
| 숫자는 실측해서 적는다 | "10분 주기"가 실제로는 1분이면 독자가 9분을 헛기다린다 |
| 배경·경위는 빼거나 맨 뒤로 | "왜 이 결정을 했나"는 대개 커밋·PR·ADR 몫 |

## 갱신할 때

**전면 재작성보다 낡은 서술을 찾아 걷는 쪽이 낫다.** 사실은 하나도 버리지 않는다.

문서가 길어서 줄여야 하면 **중복부터** 걷는다. 절이 겹치거나, 표가 본문을 반복하거나, 형제 문서와 같은 내용을 담고 있는 자리다.

⚠️ **미해결 항목을 정리하면서 지우지 않는다.** "아직 정해지지 않은 것", "확인 필요", 블로커는 남긴다. 정리는 좋지만 열린 액션이 사라지면 아무도 그게 없어진 줄 모른다.

**형제 문서와 겹치면 한쪽으로 몰고 링크한다.** 같은 절차가 두 페이지에 있으면 둘 다 낡는다.

## MCP 사용

```
mcp__atlassian__getConfluencePage     contentFormat: markdown 으로 읽는다
mcp__atlassian__updateConfluencePage  contentFormat: markdown, versionMessage 필수
```

`versionMessage` 에는 **무엇을 왜 바꿨는지** 한 줄. `수정` 말고 `미러 주기 정정 — 10분 → 1분 (API 실측)`.

## Common Mistakes

| 증상 | 고치는 법 |
|---|---|
| 절이 `구성 / 계정 / 접근 경로 / 체크리스트` 처럼 주제별 | 독자 행동 순서로 재배치 |
| 표 7개, 번호 절 8개 | 판단 기준 없는 표를 목록으로, 요약표 삭제 |
| 첫 화면에 구조 설명 | 첫 문단을 "무엇을 하면 되는가"로 |
| `최대 10분` 같은 어림수 | 실측해서 적는다 |
| 정리하면서 미해결 블로커까지 삭제 | 열린 항목은 남긴다 |

## Real-World Impact

KT 경북 GitOps 문서(2026-09-14): 구조 설명으로 시작하던 페이지를 "배포하려면 무엇을 하나"로 뒤집고, 실측으로 미러 주기 오류(10분 → 1분)를 정정. 정보는 버리지 않고 배치만 바꿔 독자가 첫 화면에서 답을 얻게 됐다.
